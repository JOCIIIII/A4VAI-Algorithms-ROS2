# X8 충돌 회피 정책 — 입력 160개판 (ONNX 묶음)

2026-10-11 내보냄. X8 묶음 (`ca_x8_onnx/agent.md`) 과 **출력·속도 조절기·명령 평활·좌표계·전처리가 모두 같다.** 달라진 것은 정책 입력에서 56개를 뺀 것 하나다 (216 → 160).

## 파일
- `ca_x8_in160.onnx` : 정책 (입력 160, 출력 3, 관측 정규화와 출력 클립 포함)
- `cfg.json` : X8 묶음과 같은 값 + `obs_drop` (뺄 칸), `obs_dim` 160
- `ca_policy_ref.py` : numpy 참조 구현. `cfg.json` 의 `obs_drop` 을 읽어 알아서 잘라낸다 (예전 묶음의 `cfg.json` 으로도 그대로 동작)

## 뺀 입력 (전체 216 기준 칸 번호)
| 뺀 것 | 칸 | 개수 |
|---|---|---|
| 속력 | 0 | 1 |
| 고도 편차 (경로 고도 대비) | 12 | 1 |
| 거리 이미지의 뒤쪽 방위 9칸 (방위 칸 12~20 = LOS 기준 135°~225°), 6줄 모두 | 27:36, 59:68, 91:100, 123:132, 155:164, 187:196 | 54 |

- 노드에서 하는 일: 예전처럼 216개를 만든 뒤 위 칸을 빼고 넣으면 된다 (참조 구현이 하는 방식). 처음부터 안 만들어도 된다
- **속도 조절기는 그대로 전체 이미지 (뒤쪽 칸 포함) 의 최솟값을 쓴다.** 뺀 것은 정책 입력뿐이다
- 남은 입력 160개: 기체 좌표계 속도 3, LOS 벡터 3, LOS 기준 속도 3, 남은 길이 1, 횡오차 1, 꺾임각 1, 지면 고도 1, 거리 이미지 6 × 23 = 138, 장애물 밀도 1, 중력 방향 3, 직전 행동 3, 정지 판정 2

## 무엇인가
- 학습 과제 `v3x8r56`, 체크포인트 `runs/wp3dx8r56_control/26-10-11_09-55-54-227308_PPO/checkpoints/agent_9600.pt`
- X8 선정 정책 (`ca_x8_noclimb.onnx`) 의 첫 층에서 해당 열을 잘라낸 뒤 같은 환경에서 9,600 스텝 더 학습한 것
- 환경·충돌 판정 (1.0 m)·보상·출력 범위·상승 금지는 X8 묶음과 같다

| 같은 방식으로 더 학습한 입력 216 정책 도착 | 0.962 | 0.889 | 0.828 | 0.761 | 0.732 | 0.834 |
| 이 정책 충돌 | 0.031 | 0.104 | 0.139 | 0.168 | 0.189 | 0.126 |

- 입력 216 정책과 차이 0.005 는 평가 오차 (약 ±0.005) 안이다
- X8 묶음의 정책 (0.806) 보다 높은 것은 입력을 줄여서가 아니라 한 번 더 이어 학습했기 때문이다 (입력 216 그대로도 같은 만큼 올랐다)
- 더 빼 본 것 (시드 3개 × 체크포인트 2개, 입력 216 정책과 같은 조건끼리의 차): 장애물 밀도 −0.018, 정지 판정 −0.019 (정지 2 % → 4 %), 기체 좌표계 속도 −0.021 — 그래서 남겼다. 이 묶음의 56개만 뺀 경우는 −0.005 ± 0.004 (오차 범위)
