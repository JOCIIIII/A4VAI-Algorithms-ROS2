# X8 충돌 회피 정책 — 30 m 판, 입력 160개 (ONNX 묶음)

2026-10-12 내보냄. 30 m 묶음(`x8_30m_onnx`)과 **출력·속도 조절기·명령 평활·좌표계·전처리가 모두 같습니다.**
달라진 것은 정책 입력에서 56개를 뺀 것 하나입니다(216 → 160). 규격 설명은 30 m 묶음의 `agent.md`를 따르십시오.

## 0. 노드에서 바꿀 것

- **2차 묶음(`x8_onnx_r2`, 10 m)에서 넘어오는 경우**: 30 m 묶음 메뉴얼 0절의 세 가지를 똑같이 적용합니다.
  - 거리 이미지를 10 m가 아니라 30 m에서 자릅니다(`d_sensor_max`).
  - 거리 정규화를 꺾은선으로 바꿉니다(`ca_policy_ref.normalize_ranges`: d ≤ 8이면 d ÷ 10, 그보다 멀면 0.8 + 0.2 × (d − 8) ÷ 22).
  - 지면 점을 30 m까지 뺍니다.
- **30 m 묶음(`x8_30m_onnx`)에서 넘어오는 경우**: 정책 파일과 `cfg.json`을 바꾸고, 관측에서 2절의 56칸을 빼고 넣습니다. `ca_policy_ref.py`는 같은 파일이고, `cfg.json`의 `obs_drop`을 읽어 알아서 잘라냅니다.

## 1. 파일

| 파일 | 내용 |

| `ca_x8_30m_in160.onnx` | **기본 정책.** 입력 160, 출력 3, 관측 정규화와 출력 클립 포함 |
| `ca_x8_30m_in160_alt.onnx` | 예비 정책. 다른 난수 시드, 이어 학습 19,200 스텝(기본은 9,600). 성능은 같은 수준 |

| `agent.md` | 이 문서 |

받은 뒤 바로 확인:

```bash
pip install onnxruntime numpy
python ca_policy_ref.py      # 두 정책 모두 "OK" 가 나와야 함
```

## 2. 뺀 입력 (전체 216 기준 칸 번호)

| 뺀 것 | 칸 | 개수 |
|---|---|---|
| 속력 | 0 | 1 |
| 고도 편차 (경로 고도 대비) | 12 | 1 |
| 거리 이미지의 뒤쪽 방위 9칸 (방위 칸 12~20 = 기준 방위에서 135°~225°), 6줄 모두 | 27:36, 59:68, 91:100, 123:132, 155:164, 187:196 | 54 |

- 노드에서는 예전처럼 216개를 만든 뒤 위 칸을 빼고 넣으면 됩니다(참조 구현의 방식). 처음부터 만들지 않아도 됩니다.
- **속도 조절기와 사각지대 기억은 그대로 전체 이미지(뒤쪽 칸 포함)를 씁니다.** 뺀 것은 정책 입력뿐입니다.
- 남은 입력 160개: 기체 좌표계 속도 3, 경로 전방점 방향 3, 기준 방위 프레임 속도 3, 남은 길이 1, 횡오차 1, 꺾임각 1, 지면 고도 1, 거리 이미지 6 × 23 = 138, 장애물 밀집도 1, 중력 방향 3, 직전 행동 3, 정지 판정 2.

## 3. 성능 (시뮬레이션, 참고)

30 m 묶음과 같은 벤치마크입니다(레벨당 1,024개 장면, 60 s 제한, 센서 모델 30 m). 검증용 시드 기준:

| 정책 | 입력 | 도달률 L0 / L1 / L2 / L3 / L4 (평균) | 충돌률 L0 / L1 / L2 / L3 / L4 (평균) |
|---|---|---|---|
| 30 m 묶음 기본 `ca_x8_noclimb_30m` | 216 | 0.97 / 0.89 / 0.82 / 0.79 / 0.76 (0.846) | 0.02 / 0.08 / 0.12 / 0.14 / 0.16 (0.104) |
| **`ca_x8_30m_in160` (기본)** | 160 | **0.96 / 0.87 / 0.83 / 0.79 / 0.75 (0.840)** | 0.03 / 0.10 / 0.13 / 0.15 / 0.17 (0.119) |
| `ca_x8_30m_in160_alt` (예비) | 160 | 0.96 / 0.87 / 0.82 / 0.77 / 0.75 (0.835) | 0.03 / 0.09 / 0.14 / 0.16 / 0.19 (0.121) |
| 30 m 묶음 기본 + 사각지대 기억 3초 | 216 | 0.98 / 0.91 / 0.84 / 0.79 / 0.78 (0.857) | 0.01 / 0.07 / 0.11 / 0.13 / 0.15 (0.094) |
| 기본 + 사각지대 기억 3초 | 160 | 0.97 / 0.89 / 0.83 / 0.80 / 0.75 (0.852) | 0.02 / 0.08 / 0.12 / 0.13 / 0.17 (0.103) |
| 예비 + 사각지대 기억 3초 | 160 | 0.96 / 0.89 / 0.85 / 0.78 / 0.77 (0.853) | 0.02 / 0.07 / 0.10 / 0.14 / 0.16 (0.099) |

- 입력 216개 정책과의 도달률 차 0.005~0.006은 평가 잡음(±0.01) 안입니다. 충돌률은 0.01쯤 높습니다.
- 선정에 쓴 시드에서는 기본 0.840, 예비 0.837이었습니다. 같은 방법으로 시드를 바꾼 세 학습의 평균은 0.834로, 입력 216개인 30 m 학습의 평균 0.838과 같은 수준입니다.
- 도달한 비행의 평균 속도는 L0에서 3.5 m/s, L4에서 2.8 m/s입니다. 경로 고도보다 1.5 m 넘게 올라간 비행은 없습니다.
- 10 m 판에서 더 빼 본 결과(장애물 밀집도 −0.018, 정지 판정 −0.019, 기체 좌표계 속도 −0.021)에 따라 이 56개만 뺐습니다. 30 m 판으로 다시 시험하지는 않았습니다.

## 4. 무엇인가

- 학습 과제 `v3x8ck56`. 기본 `runs/wp3dx8ck56_control/x8w_k56_s7/checkpoints/agent_9600.pt`, 예비 `x8w_k56_s11/checkpoints/agent_19200.pt`.
- 30 m 묶음의 기본 정책 첫 층에서 해당 열을 잘라낸 뒤(잘라낸 직후 0.828, 자르기 전 0.852, 선정용 시드) 같은 환경·같은 보상으로 이어 학습한 것입니다.
- 환경·충돌 판정(1.0 m)·출력 범위·상승 금지는 30 m 묶음과 같습니다.

## 5. 확인한 것과 아닌 것

**확인함**
- ONNX 출력 = 학습 체크포인트 출력 (최대 차이 3e-6)
- 참조 구현의 관측·WP·속도 = 학습 환경의 계산 (`scripts/check_deploy_ref.py`: 관측 4e-6, WP 6e-6 m)
- 참조 구현의 사각지대 기억 = 시뮬레이터의 기억 (`scripts/check_point_memory_bundle.py`)

**확인하지 않음**
- 이 정책의 SITL·실기 비행
- 실제 Mid-360 점군으로 만든 이미지에서의 동작. 특히 10~30 m 구간과 30 m까지의 지면 제거
